# SHAHRVAND — V1 public release definition

**Target version:** 1.0.0  
**Branch:** `release/v1.0.0`  
**Audience:** age 7+  
**Current scope:** personal progress game for learning, kindness, nature, focus, and everyday responsibility.

## Product principles

1. Start without an account, phone number, email, password, surname, or real name.
2. Nickname is optional; use a pseudonym.
3. Age is selected as a band only: 7–12, 13–17, or 18+. No exact date of birth is collected.
4. Users under 18 remain local-only. Their app profile and mission progress are not sent to a server.
5. No GPS, camera, microphone, uploads, chat, advertisements, or behavioural analytics in V1.
6. Missions require no public proof. Completion is self-reported and XP is clearly labelled as personal progress, not official verification or money.
7. No fabricated public leaderboard. A server-verified ranking is deferred until moderation and anti-abuse controls exist.
8. The UI supports Tajik, Russian, and English.
9. If the public catalogue service is unavailable, the bundled missions keep the game usable offline.

## V1 features

- Three-step-light onboarding: optional nickname, age-band selection, start.
- Seven short missions in learning, kindness, nature, community, and focus.
- Each mission may be completed once per local calendar day.
- Local XP, level, mission count, achievements, and daily progress.
- Settings for nickname, language, and local data reset.
- Public roadmap that clearly labels planned features as planned.
- Supabase-backed public mission catalogue for the 18+ mode only; read-only, no user profile or progress endpoint.
- Local catalogue fallback for all age groups.

## Backend

The connected Supabase project contains an isolated `public.shahrvand_missions` table. It holds public mission content only. RLS is enabled, and Data API roles receive SELECT only. There are no SHAHRVAND user profiles, user progress rows, auth accounts, proof uploads, or admin review records in V1.

The connected Supabase project is also used by other Khayom1 applications. SHAHRVAND uses only its prefixed mission table and does not modify their existing functions or migrations.

## Automated validation

- `gradle :app:testDebugUnitTest`
- `gradle :app:assembleDebug`
- `gradle :app:assembleRelease`
- CI checks the manifest for location, camera, microphone, and location-foreground-service permission declarations.
- Website deployment validates the landing page and privacy policy exist.

A successful build is not a substitute for physical-device testing.

## Before public distribution

- Run the Android CI and review the uploaded APK artifacts.
- Install and test on a physical Android 8+ device (onboarding, language switching, day reset, duplicate mission protection, local reset, offline fallback, and 18+ catalogue fetch).
- Review the public privacy page and complete Google Play Data safety, Target audience, and content rating declarations from the final signed APK.
- Configure GitHub Pages Source to GitHub Actions and verify the published landing page and privacy policy.
- Sign the release APK with the owner's private release keystore. V1 CI produces an unsigned release APK; no signing key is committed or generated by CI.
- Create the GitHub release and attach only the final signed APK, after the signing step is completed.

## Deferred features

Server-side proof review, trusted-admin workflow, cross-device accounts, cloud progress, public leaderboard, GPS activity validation, school/organisation programmes, and aggregate civic-impact reporting are not part of V1. They must not be shown as implemented until built, tested, and reviewed.
